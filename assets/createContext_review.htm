02Context::Setup：建立 Context 的运行资源

Setup 按图中的六个阶段执行：设置初始化状态，建立 Module 管理表和配置槽，申请溢出内存，创建默认 Stream，再处理条件同步与可选的 onlineStream，最终进入 ACTIVE。

2.1 进入 INITIALIZING，记录 userDeviceId

Setup 开始时将 Context 状态设为 INITIALIZING，并根据 Device ID 取得用户设备编号，写入 userDeviceId_。后续资源步骤成功后，状态才进入 ACTIVE。

2.2 Init()：准备 Module 管理表与系统参数

Init() 准备 Context 后续管理程序和配置所需的 Host 侧存储，并将 TearDown 执行状态置为尚未执行。

成员保存的内容与后续用途
moduleAllocator_创建并初始化 ObjAllocator<Module*>，按 Program ID 保存 Module 指针。后续 KernelLaunch 通过 Context::GetModule 查询它，并按需取得、缓存设备上的 Module。
sysParamOpt_扩展到 SYS_OPT_RESERVED，为系统配置选项预留槽。每项记录“是否已设置”和“配置值”，由后续 CtxSetSysParamOpt / CtxGetSysParamOpt 读写。

这一步建立程序管理与配置存储；算子代码在后续加载 Program、Module 时按需准备。

2.3 SetOverflowAddr()：申请溢出状态的 Device 内存

overflowAddr_ 为空时，通过 DevMemAlloc 申请 512 字节 Device 内存，保存供该 Context 后续溢出检测使用的地址。Context 在 Host 侧记录这个 Device 地址。

处理条件具体动作
支持 TS 4G 溢出内存特性使用 RT_MEMORY_TS_4G；分配成功后清零，并通过 MemAddressTranslate 得到 overflowAddrOffset_。
普通路径使用 RT_MEMORY_DEFAULT 申请该内存，地址保存在 overflowAddr_。
分配返回 RT_ERROR_DRV_OUT_MEMORY记录错误，Setup 允许继续；其他错误会向外返回，终止本次 Setup。

2.4 创建 defaultStream_，完成建流并关联 Context

aclrtCreateContext 创建的显式 Context 使用 isPrimary_ = false 分支，依次执行以下操作：

步骤对象或资源的变化
设置流标志基础标志为 RT_STREAM_PRIMARY_DEFAULT。Device 支持控制 SQ 时，再加入 RT_STREAM_FAST_LAUNCH 和 RT_STREAM_FAST_SYNC。
StreamFactory::CreateStream根据 Device 创建对应的 Stream 对象，保存到 defaultStream_。
defaultStream_->Setup()进入流自身的资源准备流程。失败时删除该 Stream，并把错误返回给 Context 的创建流程。
defaultStream_->SetContext(this)默认流记录所属 Context，形成 Context 持有默认流、默认流关联 Context 的关系。

每个显式 Context 在这里建立自己的默认 Stream。同一函数中的 Primary Context 分支直接取 Device 的 PrimaryStream_。

流内部的任务缓冲区、流 ID 与 SQ/CQ 准备过程见 createStream 复盘学习图解。

2.6 OnlineStreamInit()：按需准备 onlineStream_，进入 ACTIVE

最后调用 OnlineStreamInit(chipType)。onlineStream 用于在线运行场景，由芯片特性、运行模式及 fastCQ 条件共同决定是否创建。

条件或结果处理动作
支持 RT_FEATURE_STREAM_ONLINE 且处于 ONLINE 模式调用 TryAllocFastCq()，进一步检查 Device 的 fastCQ 标志。
fastCQ 标志已开启创建 onlineStream_，设置 fastCQ 标志，调用流的 Setup()；成功后关联当前 Context。
onlineStream 的 Setup 失败关闭 Device 的 fastCQ 标志，删除该流，回退到普通路径。这个可选优化失败不会终止 Context 的创建。

OnlineStreamInit 返回成功后，将 Context 状态设为 ACTIVE。此时 Setup 完成，外层继续登记 Context 并绑定当前线程。

03Setup 完成后的对象关系与线程绑定

对象关系创建成功后的结果
Context → DeviceContext 持有 Device 指针；同一 Device 可以被多个 Context 共享。
Context ↔ 默认 Stream显式 Context 各自创建默认 Stream，流通过 SetContext(this) 记录所属 Context。
当前线程 → Context外层先 InsertContext 登记对象，再通过 ContextSetCurrent 将它设为调用线程的当前 Context。

线程绑定时更新 curCtx_、清空 curRef_，并刷新当前 Device。连续创建 C1、C2 后，当前线程使用 C2；切换回 C1 时调用 aclrtSetCurrentContext(C1)。其他线程分别维护自己的绑定。

04Context 的失败处理与销毁

Setup 失败时，NewContext 执行 TearDown 并删除 Context。使用结束后，通过 aclrtDestroyContext 清理资源；销毁成功后标记对象待删除，线程引用归零时释放对象，最终归还 Device 引用。

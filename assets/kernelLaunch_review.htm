01rtKernelLaunch 的传入参数

从一次调用的六个入参开始：stubFunc 指定目标 Kernel，args / argsSize 提供本次参数，numBlocks 和 stm 指定启动数量与目标流。Runtime 沿这些入参准备设备代码入口、参数区和任务描述。

rtError_t rtKernelLaunch(
    const void* stubFunc, uint32_t numBlocks, void* args,
    uint32_t argsSize, rtSmDesc_t* smDesc, rtStream_t stm);
入参进入 Runtime 后的用途
stubFunc作为注册查找键定位 Kernel，取得所属 Program，再通过 Module 解析本次设备代码入口。
numBlocks指定本次 Block 数；校验后记入任务的 comm.dim，最终填入 SQE 的 header.block_dim。
args本次参数缓冲区地址；其中可包含输入、输出的 Device 地址及标量等，布局遵循 Kernel 的参数约定。装载后形成设备任务使用的参数地址。
argsSize参数缓冲区的字节数，与 args 一起封装为 rtArgsEx_t，用于参数检查和装载。
smDesc当前 rtKernelLaunch 入口将该参数标记为 UNUSED。
stm指定目标 Stream；为空时取当前 Context 的默认流。Runtime 校验流归属，后续使用该流对应的 Device 与 SQ。

以向量加法为例，args 可以按约定保存两个输入地址、一个输出地址和元素数量。输入、输出地址关联本次使用的 Device 数据内存；numBlocks 与 stm 则描述这次执行的启动方式和所在流。

02Runtime 设备任务构造

Runtime 负责将调用方给出的函数身份、参数和流，落实为设备代码入口、设备可访问的参数区，以及描述本次执行的任务信息。

2.1从执行请求找到 Kernel、Program 与设备代码入口

stubFunc 的注册映射把函数身份关联到 Kernel 与 Program。入口把 args 和 argsSize 封装为 rtArgsEx_t，校验参数后，ApiImpl 确定目标 Stream 并检查 Context 归属。StreamLaunchKernelV1 先取得任务描述，再由 InternalLaunchKernelPrepare 查询 Kernel、Program 和 Module。

Runtime 对象本次复盘需要掌握的职责
Program / ElfProgram管理注册程序、二进制与解析出的 Kernel 信息；对外以 binHandle 标识。
Kernel描述一个可执行入口，记录所属 Program、名称、入口偏移和执行类型等。
Module表示某设备上的程序加载实例，记录代码基址；GetFunction 结合 Kernel 偏移得到设备入口。
Context / StreamContext 确定执行归属并关联 Module；Stream 承接任务顺序、任务资源及 SQ。
TaskInfo / AicTaskInfo保存某次 launch 的入口、Block 数量、参数地址与资源句柄，用于构造 SQE 并跟踪回收。

当设备尚无可用 Module 时，ModuleAlloc 创建加载实例，Module::Load 取得 Program 的可加载代码数据并建立设备副本。随后 GetFunction 结合设备代码基址与 Kernel 的入口偏移，得到本次任务使用的设备入口。

2.2把本次参数、入口和启动配置合成任务

Runtime 按参数大小与流资源选择装载路径，为设备准备参数区；AicTaskInit 初始化任务，再写入设备入口、Kernel、Program 及 Block 数量。装载结果通过 SetAicoreArgs 记入任务的参数地址、长度和资源句柄。

处理步骤本次调用的变化
准备参数区大参数或无预留 PCIe BAR 时提前公共装载；可使用预留参数区的小参数在提交阶段按 taskResId 装载。
初始化任务comm.dim 记录 Block 数；funcAddr / funcAddr1 记录已解析的设备代码入口。
记录参数结果comm.args、comm.argsSize 和 comm.argHandle 记录设备可访问的参数地址、长度与回收凭据。
提交任务Device::SubmitTask 进入提交实现；fast launch 会申请持久任务槽、保存 TaskInfo，再构造 SQE。

已注册的函数信息 + 本次参数 + 启动配置与流 → TaskInfo → SQE

03Device 任务下发与执行完成

代码加载、参数装载和任务描述提交分别建立设备执行所需的内容。最后由流的 SQ 承接 SQE，设备根据其中的地址和配置执行任务。

3.1代码、参数与 SQE 的下发内容

需要分清三份内容：程序加载建立设备代码副本；参数装载建立本次调用的参数区；任务提交把 SQE 送入目标 SQ。Program、Kernel 和 Module 在 Host 上承担管理与地址解析工作，SQE 使用由它们解析得到的设备地址。

进入 Device 的内容来源Device 侧作用
可加载代码数据Module::Load 从 Program::Data() / LoadSize() 取得数据，分配或复用代码内存，再执行 H2D 加载。形成可执行代码区，由设备 PC 指向相应 Kernel 入口。
参数缓冲区从 args / argsSize 装载；普通路径执行 H2D 拷贝，预留 BAR 路径写入 copyDev 对应区域。供 Kernel 读取本次参数，其中可以包含 Device 数据地址和标量值。
SQERuntime 将 TaskInfo 转成硬件任务描述，通过驱动提交到流的 SQ。提供设备代码入口、参数地址、Block 数量与执行配置。

参数中的输入、输出地址指向已准备好的 Device 数据内存；实际张量数据由相应的数据准备流程建立。复用已有 Module 时，代码加载结果可继续使用。

3.2最终提交的 SQE 记录本次执行所需的信息

提交层调用 ToConstructSqe，把 Host 的任务描述转换为硬件 SQE。硬件 SQ 路径调用 halSqTaskSend 或 Driver::SqTaskSend，目标由流的 SQ 决定；软件 SQ 分支写入对应的 SQE 缓冲区。

运行时来源普通 AI Core SQE 中的字段含义
aicTaskInfo->funcAddrpc_addr_low / pcAddrHigh本次执行的 Device 代码入口。
aicTaskInfo->comm.argsparamAddrLow / param_addr_high设备可访问的参数区地址；部分高位按栈配置处理。
aicTaskInfo->comm.dimheader.block_dim本次启动的 Block 数量。
taskInfo->idheader.task_id流内任务跟踪所用的任务 ID。

Device 根据 SQE 中的 PC 定位代码，根据参数地址取得本次参数，并按 Block 数及其他配置执行。代码与参数在执行前通过各自的加载路径准备；已有 Module 的代码加载结果可以继续复用。

执行要点

rtKernelLaunch 六个入参的职责

stubFunc 选择 Kernel，args / argsSize 描述参数缓冲区，numBlocks 指定 Block 数，stm 指定目标流；smDesc 在当前入口中未使用。

stubFunc 与设备代码入口的关联

Runtime 查询注册映射取得 Kernel 和所属 Program，再获取设备 Module，由 GetFunction 解析出设备代码入口。

本次设备任务的构造过程

先确定目标流，查询 Kernel 和 Module 并取得设备入口，准备参数，再将入口、参数地址和 Block 数等记录为 TaskInfo。

SQE 下发与 Device 执行过程

提交实现将 TaskInfo 转成 SQE；Device 按其中的设备 PC、参数地址与启动配置执行，并推进完成状态。

01rtKernelLaunch 的入参与完整流程图

从一次调用的六个入参开始。总图展示每个入参在 Runtime 中对应的对象、处理过程，以及最终准备到 Device 上的内容。第 2 章展开图中的对象与参数分支，第 3 章展开 SQE、目标 SQ 和执行完成。

rtError_t rtKernelLaunch(
    const void* stubFunc, uint32_t numBlocks, void* args,
    uint32_t argsSize, rtSmDesc_t* smDesc, rtStream_t stm);
入参进入 Runtime 后的用途
① stubFunc传入一个指针值；Runtime 用这个值查询注册表，取得对应的 Kernel 对象，再通过 Program 和 Module 找到本次设备代码入口。
② numBlocks指定本次 Block 数；校验后记入任务的 comm.dim，最终填入 SQE 的 header.block_dim。
③ args本次参数缓冲区地址；其中可包含输入、输出的 Device 地址及标量等，布局遵循 Kernel 的参数约定。装载后形成设备任务使用的参数地址。
④ argsSize参数缓冲区的字节数，与 args 一起封装为 rtArgsEx_t，用于参数检查和装载。
⑤ smDesc当前 rtKernelLaunch 入口将该参数标记为 UNUSED。
⑥ stm指定目标 Stream；为空时取当前 Context 的默认流。Runtime 校验流归属，后续使用该流对应的 Device 与 SQ。

02Runtime 对象与任务准备

沿总图的分支展开：先确定流和设备，再查找 Kernel、准备代码入口，随后说明 Block 数、参数区以及 TaskInfo 中的汇合关系。

2.1⑥ stm → Stream / Context / Device

stm 传入目标流句柄。Runtime 解包得到 Stream；为空时取当前 Context 的默认流，并检查流与当前 Context 的归属关系。

图中对象本次调用中的作用
Stream承接本次任务，记录关联的 Device 和 SQ ID。
Context提供当前执行环境，检查流归属，并在后续查询 Program 对应的 Module。
Device确定本次使用的设备，提供任务提交和资源管理能力。

StreamLaunchKernelV1 先通过 AllocTask 取得任务描述，再准备 Kernel。此时确定任务归属；后续解析出的入口、Block 数和参数地址继续写入这份任务。

stm → Stream → Context / Device；Stream 的 SQ ID 确定最终提交目标

2.2① stubFunc → KernelTable → Kernel

stubFunc 传入一个指针值。注册阶段已建立这个值与 Kernel 对象的对应关系；启动时，Runtime 用同一个值查询 KernelTable。

registeredKernel = rt->kernelTable_.Lookup(stubFunc);

查到的 Kernel 记录所属 Program、入口偏移和执行类型。Runtime 检查 Kernel 是否存在、执行类型是否适合当前路径，再从 Kernel 取得 Program，进入下一节的代码加载流程。

2.3Program / ElfProgram → Module → 设备代码区

沿首图中 Kernel 向下的分支，Runtime 从 Kernel 取得所属 Program，再通过 Context::GetModule 查询该 Program 在当前 Device 上的加载实例。

图中对象保存的内容与处理动作
Program / ElfProgramHost 侧管理已注册的二进制和解析信息。普通 ELF 路径通过 Data() 与 LoadSize() 取得可加载数据及长度。
ModuleHost 侧管理该 Program 在当前 Device 上的加载实例。已有实例时复用；首次加载时申请代码内存，并把可加载数据复制到 Device。
设备代码区Device 内存中的机器指令及可加载数据。Module 记录代码基址，Kernel 记录各自的入口偏移。

ElfProgram 保存的二进制与 ELF 解析信息

ElfProgram 继承 Program。它使用 Program 的 binary_ 保存二进制缓冲区地址，通过 elfData_ 保存 ELF 解析信息，通过 kernels_ 保存解析出的各个 Kernel 信息。

字段保存的内容及用途
binary_Host 上的二进制缓冲区地址，提供 ELF 解析和代码加载的数据来源。
elfData_->elf_headerELF 文件头，描述二进制的基本格式及相关表的位置、数量等信息。
elfData_->section_headers节头表。每个节头记录类型、文件内偏移、大小和对齐要求等信息，Runtime 据此定位、解析对应内容。
elfData_->text_offset
elfData_->text_size		本实现选定的可加载数据在二进制中的起始偏移和字节数，分别用于计算 Data() 和 LoadSize() 的返回值。
elfData_->kernel_num解析出的 Kernel 数量，用于遍历 kernels_ 中的 Kernel 信息。
kernels_[i].name
offset / length		第 i 个 Kernel 的名称、入口偏移和代码长度。名称用于识别 Kernel，入口偏移用于后续定位设备代码入口。
kernels_[i].metaInfoKernel 元信息，包括函数类型 funcType、AIC/AIV 配比 taskRation、最小栈空间 minStackSize 和参数描述 paramInfos 等，用于形成 Kernel 属性及执行配置。

从 ELF 解析结果到设备代码入口

需要加载时，Module::Load 调用 Program 的 Data() 与 LoadSize()，取得待复制数据的起点与长度，再准备设备代码区。普通 ELF 路径中的地址关系如下：

加载数据起点 = binary_ + elfData_->text_offset
加载数据长度 = elfData_->text_size
设备执行入口 = Module 的设备代码基址 + Kernel 的入口偏移

同一 Program 在同一 Device 上复用一个 Module，多个 Kernel 通过各自偏移定位入口。普通 ELF 路径中，Module::GetFunction 结合设备代码基址与 Kernel 的入口偏移，得到本次执行的设备 PC。

代码按需加载到 Device；解析出的设备 PC 进入 TaskInfo / AicTaskInfo

2.4② numBlocks → 启动数量校验

numBlocks 指定本次启动的 Block 数，进入内部接口后使用 coreDim 表示。Runtime 检查其范围为 1 至 65535，随后以 uint16_t 传入任务初始化。

初始化任务时，这个值记入 aicTaskInfo.comm.dim；构造 SQE 时，再写入 header.block_dim。

numBlocks → coreDim 校验 → comm.dim → SQE 的 block_dim

2.5③ args / ④ argsSize → rtArgsEx_t → 参数装载 → 设备参数区

args 提供本次参数缓冲区的地址，argsSize 提供字节数。入口将两者封装为 rtArgsEx_t，设置拷贝标记，并检查参数地址和长度。

以向量加法为例，参数块可以按 Kernel 约定保存两个输入的 Device 地址、一个输出的 Device 地址，以及元素数量。输入、输出的实际张量内容存放在这些地址指向的数据内存中。

图中的参数装载处理方式
公共装载路径大参数或无预留 PCIe BAR 时提前装载；通过参数装载接口准备设备可访问的参数区，普通路径执行 H2D 拷贝。
预留 BAR 路径可使用预留参数区的小参数，在提交阶段按 taskResId 装载，写入 copyDev 对应区域。
装载结果SetAicoreArgs 把设备可访问的参数地址、字节数与回收句柄写入任务。

args / argsSize → rtArgsEx_t → 设备参数区；参数区地址进入 comm.args

2.6TaskInfo / AicTaskInfo：汇总入口、Block 数和参数地址

首图中的设备 PC、启动数量和参数装载结果，最终汇入同一次 launch 的 TaskInfo / AicTaskInfo。这些 Host 侧字段用于后续构造 SQE，并跟踪本次任务的资源。

上游来源任务中的字段用途

AicTaskInit 初始化任务并设置 Block 数，后续填写设备入口、Kernel 和 Program；SetAicoreArgs 记录参数装载结果。预留 BAR 路径的参数在提交阶段完成装载。

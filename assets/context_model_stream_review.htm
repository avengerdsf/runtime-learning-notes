算子本身的结构：编译后的 ELF 二进制

这里展开编译产物本身包含的内容。ELF 文件头与节头信息描述布局，代码节保存机器指令，元数据记录算子执行属性，符号表与字符串表提供 Kernel 名称、函数位置和长度。

一个 ELF 可以包含多个 Kernel。符号表与字符串表提供名称、函数位置和长度；元数据补充各个 Kernel 的执行属性。

SQE：SQ 中的提交条目

SQ（Submission Queue）是提交队列，SQE（Submission Queue Entry）是队列中的提交条目。TaskInfo 是 Host 侧任务记录；Runtime 按任务类型把它转换为一个或多个 SQE，再提交到 Stream 对应的 SQ。

当前普通 AI Core 计算任务对应一个 SQE；v100 内存等待任务会构造多个 SQE。SQE 中的 PC 和参数地址分别定位设备代码与参数区，实际代码、参数内容保存在对应的 Device 内存中。

创建、执行与清理

创建与绑定：Model 和 Stream 在同一 Context 中独立创建，创建顺序不限。绑定后，普通流从 Context::streams_ 转入 Model::streams_，流的 Context_() 保持原归属；一条流同一时刻最多绑定一个 Model。

执行：E 是未绑定模型的执行流，可由默认流或指定用户流承担。E 上的模型启动 Task 启动 M1 的入口流 A；B、C 是待激活模型流，由控制 Task 关联后续调度。

清理：业务结束并按需同步后，解绑或销毁普通 Model；成功解绑的普通用户流回到 Context 管理，再按需要销毁 Stream 和 Context。

补充

自动拆分：任务构建容量达到条件时，Runtime 可以增加从流；新增流仍属于原 Context，并加入同一 Model。

线程切换：切换当前 Context 后，已有 Model 和 Stream 保持原来的 Context 归属；操作这些对象时，需要满足对应的 Context 校验。

总引导按模型构建、执行、清理三步梳理对象关系

按三步理解完整使用过程：在共同 Context 中创建并绑定对象、记录模型任务，再启动模型执行，最后解绑和释放资源。自动拆分补充任务构建容量，线程切换补充 Context 校验。

01Model 与 Stream 独立创建，绑定后由 Model 分组管理

Model 与持久 Stream 在同一 Context 内独立创建。创建顺序不限，两者创建完成后再绑定；绑定改变流的管理集合，Context_() 保持不变。绑定后记录 task、结束图并调用 LoadComplete，完成模型构建。流的资源初始化与三种绑定方式，见 createStream 图解。

02执行流启动 Model，模型入口流与待激活流承载任务

执行流 E 提交模型启动任务，本例的模型入口流 A 开始运行，再由控制 task 关联待激活流 B、C 或选择执行位置。A、B、C 都是绑定 M1 的模型流：A 为 HEAD 入口流，B、C 为 WAIT_ACTIVE 待激活流。默认流描述 Context 提供的流，执行流描述启动模型的用途；E 可以选用默认流或指定的用户流。点击 task 方块可放大查看内部结构。

名称含义与用途本图对应
默认流Context 的 defaultStream_；部分执行路径未指定流时选用可以承担 E 的执行用途
执行流提交模型执行任务，启动 ModelE：默认流或指定用户流
模型入口流已绑定 Model；HEAD 角色登记在 headStreams_，作为模型启动入口A：Model_() = M1
模型待激活流已绑定 Model；WAIT_ACTIVE 角色等待控制任务激活B、C：Model_() = M1

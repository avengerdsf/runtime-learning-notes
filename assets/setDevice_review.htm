setDevice 复盘学习图解

SetDevice 在首次使用设备时建立任务执行所需的设备级资源，最后将 Primary Context 设为调用线程的当前 Context。设备初始化分为 RawDevice::Init 的资源准备和 RawDevice::Start 的运行启动。

01SetDevice 如何进入设备初始化

SetDevice 校验并转换用户设备编号，retain 对应 Primary Context；Primary 需要初始化时取得 Device，Device 首次 retain 时先准备 AI CPU 执行环境，再构造 RawDevice，依次执行 Init 和 Start。

02RawDevice::Init：创建设备级资源

Init 准备任务执行所需的引擎、分配器、缓冲和管理对象。前半段打开设备并读取芯片特性、设备属性、运行模式与分组信息，随后创建以下资源。资源大小多取自 DevProperties，功能开关控制可选分支。

2.2 执行引擎、参数池、任务池与内核池

资源位置创建内容与用途创建条件
engine_Host根据平台创建 StarsEngine、DirectHwtsEngine 或 AsyncHwtsEngine，并调用 Init；STARS 在此设置完成等待超时。本路径；具体类型由平台决定
spmPool_Host + Device HBM创建地址记录数组和小块分配器；预分配首批 HBM，按 512 字节小块提供 SPM 空间，初始数量受设备特性控制。DEVICE_SPM_POOL
argLoader_Host + Device建立常规、大参数/超大参数、Handle、KernelInfo 和可选 PCIe BAR 参数池；供算子参数加载与地址管理使用。参数块分配随拷贝策略建立，动态 randomAllocator 先保存管理状态。常规参数池在非 UB 连接下创建；扩展池按能力
ubArgLoader_Host + Device HBMDavid 适配创建 UB 参数池和 Handle 池；预分配 HBM、Host 参数块及 Tseg 信息，供 UB 参数传输。David 适配且 ConnectUbFlag 为 true
taskFactory_Host创建 TaskAllocator，按对齐后的 TaskInfo 大小预分配任务块；首批容量参数为 INIT_TASK_CAPACITY（1024），供任务分配与回收。本路径
kernelMemPoolMng_Host + Device HBM创建 MemoryPoolManager；支持内核池时，默认初始化一个 2 MiB 内存池和 Host 空闲块表，供内核内存分配。底层使用 HBM。管理器在本路径创建；池初始化要求 KERNEL_MEMORY_POOL
modulesAllocator_Host建立 Module 引用对象首批存储块，以及分块指针、互斥锁和活跃计数数组，管理设备上的 Module 记录。本路径

BufferAllocator 构造时就申请首批内存。SPM、参数池和任务池会沿其分配回调产生实际内存占用；首批数量、块大小和内存位置需要结合各自配置与回调判断。

参数拷贝策略对应哪些实际资源
  • 同步拷贝：参数池申请设备 HBM。
  • 异步 PCIe DMA：申请设备 HBM，并尝试准备 Host 中转缓冲及逐块 DMA 地址映射。
  • PCIe BAR：申请 P2P HBM 并执行 PcieHostRegister。
  • UB：申请设备 HBM、Host 缓冲和 Tseg 信息，建立逐块地址记录。

策略选择由参数大小、运行模式、驱动能力和设备特性共同决定。

03RawDevice::Start：建流、启动引擎并分配运行资源

Start 将设备级管理资源接入实际运行：分配栈、创建默认流、启动引擎，再准备控制与诊断通路。若 primaryStream_ 已存在，Start 直接返回成功。

资源位置创建内容与用途创建条件
设备运行栈DeviceSTARS 分配 普通栈及按配置启用的自定义栈；David 适配还按 SIMT 条件申请并对齐 simtStackPhyBase_。平台、特性和用户栈配置
primaryStream_Host + 驱动 / Device创建默认 Stream 并执行其 Setup，准备流身份、队列和任务资源；具体内容由所选 Stream 实现决定。默认流尚未存在
运行引擎线程Hostengine_->Start 启动执行环境；StarsEngine 创建 Monitor 线程，非 PC 路径创建/复用 Runtime 的 RAS 上报线程，按能力创建回收线程。具体引擎；回收线程受 TASK_RECYCLE_THREAD 控制
ctrlSQ_Host + 驱动 / Device创建控制 SQ 对象和独立内部 Stream，并执行 Setup，准备流 ID、SQ/CQ 等资源，承载清流、Notify 重置和模型控制命令。DEVICE_CTRL_SQ
deviceErrorProc_ / RingBufferDevice + 初始化用 Host 缓冲按 ringbufSize 申请设备故障缓冲，写入 Runtime 能力并下发地址；快速 RingBuffer在毫秒级超时能力支持时由驱动分配并初始化。非 PC 且 ringbufSize 非 0；Fast RingBuffer 另受超时能力控制
errMsgObj_ / errMsgBuf_Host + Device创建 AI CPU 错误信息对象，申请并清零 DEV_ERR_MSG_BUF_TOTAL_LEN 大小的设备缓冲，再将地址和长度配置给 AI CPU。非 PC、DFX_AICPU_ERROR_MESSAGE 且初始化接口存在
profSwitchAddr_Device HBM申请一个 uint64_t（8 字节）并写入 0，保存内存等待 Profiling 的开关。MEM_WAIT_PROF

同阶段还读取 STARS / TS 版本、互联控制地址和 SwapBuffer 信息，并用 InitResource 记录 Cube / Vector 核数量及资源限制；这些查询和配置参与后续执行参数的确定。

04Context 绑定、引用与失败回收

  • Context 新建：Primary 槽没有 Context 对象时才新建；已有对象时复用，retain 从 0 开始时执行初始化。源码
  • 默认流绑定：Primary Context 将 defaultStream_ 指向对应 Device 的 PrimaryStream_，流再记录所属 Context。源码
  • 线程切换：SetDevice 设置 curRef_ 并清空 curCtx_，让调用线程使用该 Primary Context。源码
  • 引用释放：成功 Set 增加 retain，普通 Reset 减少 retain；最后一次释放关联资源，当前工作区保留未初始化的 Context 对象以供重新初始化。源码

Init 失败按错误标签逆序回收已创建的池、加载器、引擎和 SQ 地址表，最后关闭驱动设备；Start 失败根据失败位置停止设备运行，释放栈和默认流；外层 DeviceRetain 再删除失败的 Device 并回收本次启动的执行环境。Init 回收 · Start 回收 · 外层回收

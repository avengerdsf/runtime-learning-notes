createStream 复盘学习图解

Runtime 从当前 Context 取得 Device，构造用户 Stream，建立任务管理与队列资源，最后登记归属并返回句柄。创建后的流归属当前 Context；普通 STARS 流准备成对 SQ/CQ，完成查询与预留资源按配置建立。

03根据流标志选择普通队列绑定或自动拆分路径

Context 先 SetContext(this)，再选择初始化方式。普通流调用 Setup；持久流在 Host、TS 和 Driver 都支持自动拆分且满足 flags 条件时，调用 SetupForAutoSplit。初始化路径由流标志与设备能力共同决定。SetupWithoutBindSq 供内部 software SQ 请求使用，公开创建主链传入的 software SQ 开关为 false。

三种初始化方式分别解决任务提交、容量扩展和捕获绑定

三种方式的核心作用分别是常规任务提交、持久模型流自动扩容、捕获任务按需绑定硬件队列。自动拆分的容量处理以下述当前 v200 实现为依据。

方式核心作用
Setup建流时准备队列关联，供常规任务提交与回收。
SetupForAutoSplit保存模型任务，按容量扩展为主流＋从流。
SetupWithoutBindSq捕获阶段先保存任务，执行准备时按需申请并绑定硬件队列。

自动拆分有两层容量处理：Host 缓冲放不下时，增加 128 KiB，继续使用当前流；单流容量接近上限时，创建从流接续任务。容量按 SQE 条目数计算，一个 task 可能产生多个 SQE。当前实现将已有 SQE、本次 SQE与预留空间合计，达到 32767 时创建从流，并加入同一 Model。

04Stream::Setup：建立流资源

4.1在 Host 建立任务管理，在设备侧准备流 ID、队列与完成查询

普通 STARS Stream 的 Setup 依次建立任务记录、驱动身份、SQ/CQ、完成查询及参数管理状态。创建一条流，就是准备后续任务提交、跟踪和回收所需的资源。任务资源预留和 Logic CQ 有条件，PcieArgManage 在此只初始化管理对象；业务 task 由后续提交接口加入。

资源实际准备内容作用与条件
Host 任务编号缓存taskPublicBuff_、davinciTaskList_：uint32_t 数组记录 task ID；前者受发送/回收分离配置控制，后者还要求支持异步回收。
队列位置与提交记录posToTaskIdMap_：uint16_t 数组；wrRecordQueue_.queue：uint32_t 数组大小按 rtsqDepth；前者保存位置到 task ID 的映射，后者记录 SQE 位置。位置表初始化为 0xFFFF，记录队列清零。
Stream 身份驱动分配 streamId_；登记 ID → Stream*后续驱动调用、调度与资源释放使用流 ID。
设备执行计数executedTimesSvm_：sizeof(uint16_t) 内存STARS 能力分支分配并初始化为 0xFFFF；用于记录执行计数。
SQ / CQ常规 STARS 成对分配，保存 sqId_、cqId_SQ 承载 SQE；CQ 提供完成反馈。队列尺寸由设备属性与驱动配置决定。
完成查询与队列访问logicalCqId_、sqRegVirtualAddr_Logic CQ 按线程模式获取并绑定；SQ 寄存器映射由驱动查询，设备地址表存在时写入对应地址。
任务资源预留TaskResManage 与 taskResBaseAddr_能力和线程模式满足时预留 TaskRes 缓存；FAST_LAUNCH 路径还可准备 BAR 缓冲。预留失败允许继续。
参数管理argManage_ = new PcieArgManage(this)此处建立管理对象。构造器保存 Stream 指针；参数池内存由后续 CreateArgRes / MallocArgMem 准备。

4.2向驱动申请 STARS 成对 SQ/CQ，再按配置绑定 Logic CQ

Setup 把流配置交给队列管理器，最终由 halSqCqAllocate 分配设备队列资源。普通 STARS 路径的 SQ/CQ 一一对应；返回队列 ID 后，Runtime 保存字段并登记映射。Logic CQ 是另一条按线程模式准备的完成查询通路。

交给驱动或写回的内容源码动作与作用
streamId：流编号驱动分配给这条 Stream 的编号。申请队列时，用它标明队列对应哪条流；资源回收也会使用该编号。
priority：调度优先级告诉驱动这条流按哪个优先级调度。值来自创建参数，入口先裁剪到 0 至 7，再随队列申请传给驱动。
groupId：设备资源组编号选择这条流使用哪组设备计算资源。组配置包含 AI Core、AI Vector、AI CPU 和 SDMA 等资源数量；编号从当前线程或设备的组设置取得。
其他流设置satMode 指定溢出处理模式，overflowEn 指定溢出检查开关；同时传入线程配置和 SQ 类型。
队列布局NormalSqCqAllocate 根据设备属性设置 SQE/CQE 尺寸与深度；Host 记录数组深度和驱动队列深度分别取各自配置。
分配结果halSqCqAllocate 返回 sqId/cqId；队列管理器登记映射与引用数，Setup 再写入 Stream 字段。
资源不足Setup 仅在对应资源不足错误下尝试回收捕获模型队列或归还池中空闲队列，再重试；最终失败进入创建回收路径。
SQ 寄存器访问驱动取得 sqRegVirtualAddr；存在设备地址表时按 sqId 写入对应表项，供后续队列访问使用。

4.2.1Logic CQ 按线程模式获取，再绑定到 Stream

当 GetDisableThread() 为 true 时，普通流查询已有 Logic CQ，缺少记录时调用 LogicCqAllocateV2。取得 ID 后，用 StreamBindLogicCq 建立流与完成查询通路的关联。绑定 DVPP 组的流使用组内 Logic CQ；其他线程模式下，该函数直接返回。

06创建失败时按已取得的资源执行回收

输出指针、flags 或当前 Context 校验失败时直接返回；Stream 对象或资源初始化失败时，Context 进入对应错误路径。Setup 失败会 DeleteStream，并将 Context 的输出结果置空。流创建完成后，若失败模式配置失败，ApiImpl 会调用 StreamDestroy 尝试回收该流。可选 TaskRes 等预留资源失败允许继续初始化。

07使销毁句柄失效并按回收路径释放 Stream 对象

销毁入口检查句柄与捕获状态，并确认 Stream 属于当前 Context。Context 先移出用户流，再检查 Model 绑定和处理 pending 任务，随后使句柄失效并执行 TearDown。销毁成功使句柄不可再用，对象可能在维护任务回收时才删除。部分特性或无线程路径直接删除；失败且对象仍可保留时，恢复句柄与原有归属。

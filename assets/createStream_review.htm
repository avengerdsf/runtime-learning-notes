createStream 复盘学习图解

Runtime 从当前 Context 取得 Device，构造用户 Stream，建立任务管理与队列资源，最后登记归属并返回句柄。创建后的流归属当前 Context；队列共享与最终释放方式受平台及流配置影响。

Runtime · 工作区基线 e16734560 · 2026 年 10 月 13 日

源码范围：Runtime 创建入口与 Context 建流；资源初始化以 v100 普通 Stream 为主，v200/v201 标注工厂对应实现。

01校验创建参数并将优先级限制在有效范围

rtStreamCreate 使用默认 flags，rtsStreamCreate 从配置属性中提取 flags 与 priority，两者都进入 rtStreamCreateWithFlags。ApiErrorDecorator 检查输出指针和 flags，再调整优先级。越界 priority 会裁剪到 0 至 7；不支持的 flags 会返回错误。

03根据流标志选择普通队列绑定或自动拆分路径

Context 先 SetContext(this)，再选择初始化方式。普通流调用 Setup；持久流在 Host、TS 和 Driver 都支持自动拆分且满足 flags 条件时，调用 SetupForAutoSplit。初始化路径由流标志与设备能力共同决定。SetupWithoutBindSq 供内部 software SQ 请求使用，公开创建主链传入的 software SQ 开关为 false。

三种初始化方式分别解决任务提交、容量扩展和捕获绑定

三种方式的核心作用分别是常规任务提交、持久模型流自动扩容、捕获任务按需绑定硬件队列。自动拆分的容量处理以下述当前 v200 实现为依据。

方式核心作用
Setup建流时准备队列关联，供常规任务提交与回收。
SetupForAutoSplit保存模型任务，按容量扩展为主流＋从流。
SetupWithoutBindSq捕获阶段先保存任务，执行准备时按需申请并绑定硬件队列。

自动拆分有两层容量处理：Host 缓冲放不下时，增加 128 KiB，继续使用当前流；单流容量接近上限时，创建从流接续任务。容量按 SQE 条目数计算，一个 task 可能产生多个 SQE。当前实现将已有 SQE、本次 SQE与预留空间合计，达到 32767 时创建从流，并加入同一 Model。

07创建失败时按已取得的资源执行回收

输出指针、flags 或当前 Context 校验失败时直接返回；Stream 对象或资源初始化失败时，Context 进入对应错误路径。Setup 失败会 DeleteStream，并将 Context 的输出结果置空。流创建完成后，若失败模式配置失败，ApiImpl 会调用 StreamDestroy 尝试回收该流。可选 TaskRes 等预留资源失败允许继续初始化。

08使销毁句柄失效并按回收路径释放 Stream 对象

销毁入口检查句柄与捕获状态，并确认 Stream 属于当前 Context。Context 先移出用户流，再检查 Model 绑定和处理 pending 任务，随后使句柄失效并执行 TearDown。销毁成功使句柄不可再用，对象可能在维护任务回收时才删除。部分特性或无线程路径直接删除；失败且对象仍可保留时，恢复句柄与原有归属。
